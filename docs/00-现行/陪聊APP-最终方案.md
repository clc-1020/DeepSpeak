# 个人自用陪聊 App —— 最终方案

> **状态：现行（仅架构层）** ｜ 模块 1–9 的架构与设计仍有效；v1 的功能范围已被 v2 超越。
> 本文档随代码演进，细节以代码与本目录其他现行文档为准。

> 自包含文档，不依赖对话上下文。供实现者（AI 或人）按功能逐项开发。

---

## 一、项目定位与硬约束

**目标**：个人自用的安卓陪聊 App。接入大模型后像真人一样：记得用户、时不时主动找用户、主动消息有真实内容（基于记忆与上下文生成，不是话语池随机挑）。

**硬约束**：

1. 纯客户端，无服务器、无后端、电脑不常驻。
2. API Key 由用户在 App 内自行填写。
3. 安卓手机，已 root（可用 root 加白名单解决保活）。
4. 以后可能分享给别人，届时每人自填 Key。
5. 进程平时不常驻，靠系统级调度唤醒，执行完退出（省电）。
6. 通知用本地高优先级通知（`IMPORTANCE_HIGH`）实现微信式顶部弹出，不用 FCM/厂商推送。

## 二、开发方式

蓝图先行 + 分功能迭代：

1. 先定整体架构（本文档）。
2. 把功能列成有依赖顺序的清单。
3. 每次让 AI 实现一个功能；开工先读「项目规则文件」，做完更新规则文件与进度。
4. 每个功能带验收标准（见第七节）。

不要一次性把所有功能丢给 AI 实现。

## 三、功能清单

### 模块 1：基础聊天

| 功能 | 说明 |
|---|---|
| 对话界面 | 流式输出、多轮上下文、本地保存聊天记录 |
| 模型配置 | 用户自填 API Key、选择模型、切换 |
| 人设设定 | 自定义角色性格、说话风格、称呼 |
| 无后端 | 纯客户端，数据存本地 |

### 模块 2：记忆系统（三层）

| 功能 | 说明 |
|---|---|
| 短期记忆 | 最近 30 天的事，带淡忘分，随时间衰减 |
| 长期记忆 | 关于用户的稳定事实、偏好，跨会话记住 |
| 每日日志 | 按日期存事件流水，带绝对时间戳 |
| 语义去重 | 新记忆与旧的语义重复就更新旧的，不膨胀 |
| 时间锚点 | 「下周三」当场换算成绝对日期，不会失效 |
| 淡忘机制 | 不删除，只是越来越难被召回，内容一直可查 |
| 记忆管理界面 | 查看 AI 记住了什么，手动编辑/删除/新增（如「记住我对花生过敏」） |

**心情 mood**：

- 字段：`normal / happy / low`，每轮对话后更新，生成主动消息时带入以调整语气。
- 更新方式：一次**独立的额外模型调用**——不复用主对话会话 ID，只带「system 指令 + 最近 3~5 轮对话 + 当前 mood」，要求输出 JSON `{"mood":"...","reason":"..."}`。建议用同家轻量便宜模型。输入输出不写回主对话历史，不占主对话上下文。
- 失败兜底：输出格式错/超时 → 保持原 mood，不影响主对话。
- 一次调用可同时产出 mood 与「追问回复判定」（见模块 3），省调用。

### 模块 3：主动发消息

#### 3.1 三条触发线

1. **定时兜底**：WorkManager 每几小时检查一次，设「有网才执行」约束。
2. **事件预约**：`setAlarmClock` 精确唤醒，仅用于「明天面试」这类一次性、有具体时间点的事件。
3. **沉默检测**：长时间没互动触发，并入定时检查判断。

#### 3.2 统一待发队列 + 优先级调度

- 所有触发源（定时兜底 / 事件预约 / 追问链 / 特殊日期 / 环境关心）不直接发消息，统一往「待发队列」投任务，由一个调度器**串行处理**——规则只写这一处，消除并发竞态。
- 出队优先级（同级按时间先后）：
  ```
  用户指令提醒（叫床/监督/一次性事件） > 追问链 > 特殊日期/节日 > 环境钩子 > 定时兜底闲聊
  ```
  高优先级先处理；同一时刻多条时低优先级丢弃或顺延。
- 冷却/勿扰/每日上限作为最后闸门，在出队时统一检查。
- 不采用「原子锁 + 上次发送时间」方案——它可能让闲聊抢在叫床前发出。

#### 3.3 决策闸门（仅用于 AI 自发主动消息；纯规则不调模型）

- 勿扰模式：开启且处于勿扰区间时，按该模式设定处理（不发语音；是否发通知由该模式独立开关决定）。
- 冷却时间：距上次任意交互 < 2 小时不发。
- 回复率驱动：近 7 天回复主动消息比例，高则缩短间隔、低则拉长（<20% 降到一天一次）。
- 全局上限：一天最多 3 条。
- 无钩子不发：记忆钩子和环境钩子都召不出合适的就跳过。

**指令型提醒绕过闸门**：用户明确指令的定时提醒（「明天 7 点叫我起床」）绕过冷却/降频/无钩子三条，到点必执行；但仍受勿扰模式约束。

#### 3.4 钩子召回

- **优先级**：环境钩子优先于记忆钩子（环境有时效性）；无合适环境钩子时才用记忆钩子。
- **记忆钩子**：从三层记忆按 `得分 = 时间新鲜度 × 权重 + (当前时间 - 上次提起) × 久未提及加分 - 淡忘分` 选 TOP 1。
- 发过的钩子打「已提起」标记避免复读。
- **打分三态**：
  - 默认（不回复也不点按）：分数不变，只按淡忘分衰减；不存在「不回复就扣分」。
  - 回复了主动消息：对应记忆加分，更易召回。
  - 点「别提这个」1 次：降权 + 30 天冷却，到期恢复；点 2 次：永久拉黑（记忆不删，用户主动问仍能答）。
- 所有记忆被冷却/拉黑时：退回环境钩子；仍无则跳过不发（不算 bug）。新记忆会随正常对话继续产生。

#### 3.5 特殊日期与节日

- **生日/纪念日**：存进长期记忆（只录一次），每天定时检查时若「今天命中某条重要记忆的日期」→ 强制设为当天钩子优先发祝福。不用每年重设。
- **内置节日表**（用户无需录入）：
  - 公历节日（国庆、元旦、劳动节等）：日期写死。
  - 农历节日（春节、元宵、端午、七夕、中秋、重阳）：预生成 2026–2036 公历映射表，静态 JSON 打包，运行时只查表、不引入农历库。2036 年后发新版更新。
  - 命中节日 → 强制设为当天钩子；把「节日 + 人设 + 最近对话」交给模型生成有语境的祝福，不发模板话。
- 一次性事件仍走 3.1 的精确闹钟，与特殊日期机制并存。

#### 3.6 追问型任务 / 监督链

任何事件预约创建时，由额外 AI 判断三件事：要不要追问、间隔多久、什么条件停止（不靠「监督」关键词硬触发）。

- **创建**：用户说「7 点提醒我吃早餐」→ 主对话正常回复，额外 AI 抽取任务存本地：
  ```json
  {
    "type": "event_with_followup",
    "task": "吃早餐",
    "first_at": "2026-11-21T07:00",
    "need_followup": true,
    "followup_interval_min": 15,
    "stop_condition": "用户表示已吃早餐 或 主动取消（如『来不及了不吃了』）",
    "state": "pending",
    "followups_done": 0
  }
  ```
  若 `need_followup=false`（如「7 点提醒我看新闻」）→ 退化为普通一次性提醒。
- **到点**：7:00 发「吃早餐没？」→ `state=waiting_reply`。
- **循环判定**（每次追问后）：用额外 AI 判 mood + 是否满足停止条件（可与 mood 调用合并）：
  - 「吃了/正在吃」→ 回「好，那你慢慢吃」→ done。
  - 「还没」→ 回「快去吃早餐」→ 挂 15 分钟闹钟 → 再问 → 循环。
  - 「来不及了不吃了」→ 语义判定为放弃 → done。
  - 没回复 → 到点温和追问。
- 停止条件是**语义判断**，不是关键词匹配。
- 追问绕过决策闸门，受勿扰模式约束；寄生在现有调度（每次唤醒先看有无到点追问任务）。
- 兜底：绝对上限 `max_followups`（默认 5 次）防无限骚扰；额外 AI 判断失败 → 默认停止追问。
- 此模块复杂度最高，单独实现、单独测试。

#### 3.7 生成与送达

- 生成层：钩子（环境/记忆/节日）+ 关系摘要 + 最近几条对话 + mood + 环境数据 → 官方 API 生成自然话语。
- 送达层：本地 `IMPORTANCE_HIGH` 通知顶部弹出，点击直达对话页并插入对话历史。
- 语音层：若语音开关开启，用系统 TTS 念出来（见模块 5）。
- 勿扰：勿扰区间内不自动念语音；是否发通知由勿扰模式独立开关决定。
- 测试模式：设置里「立即触发一次主动消息」按钮，手动跑完整链路（决策→召回→生成→通知→语音）。

### 模块 4：省电设计

| 要点 | 说明 |
|---|---|
| 进程不常驻 | 靠 BroadcastReceiver / WorkManager Worker 被系统拉起，执行完自然结束；绝不开前台 Service 常驻（语音唤醒开启时除外） |
| WakeLock | 唤醒后拿 `PARTIAL_WAKE_LOCK`，任务结束 release |
| 有网才干活 | WorkManager 用 `setRequiredNetworkType(CONNECTED)`；AlarmManager 自己检查，没网重新预约 |
| Doze 穿透 | 定时兜底用 `setExactAndAllowWhileIdle()`；事件预约用 `setAlarmClock()`（能穿透深度 Doze） |
| 国产 ROM | 引导加电池优化白名单、允许自启动、允许后台运行（root 可自动处理，见附录 A） |
| 不做预热 | 第一版不提前唤醒预热，到点直接生成+发 |

### 模块 5：语音输出 / TTS

- 用安卓系统 `TextToSpeech` API，不内置合成模型；枚举 `getEngines()` 让用户选引擎并设默认。
- 无引擎时：明确提示「请安装语音引擎」，不内置离线引擎、不做其他降级。
- 朗读时机：
  - 对话回复：整段生成完后一次性念（不逐字、不边生成边念）。
  - 主动消息：通知弹出后后台自动念，不需点开通知；设置里可关。
  - 勿扰：勿扰区间内主动消息不自动念语音；对话手动点按朗读不受勿扰影响。
- 进程短暂停留：唤醒后可停留 5 分钟供用户续聊；朗读期间保持进程与 WakeLock，播完释放，5 分钟到即结束。
- 语速/音调用 `setSpeechRate()` / `setPitch()`，设置里给语速滑块。
- TTS 初始化异步（`onInit`），需处理「初始化未完成就收到消息」的队列；注意后台 Service 中的可用性。

### 模块 6：环境感知（位置 / 天气 / 时间）

让 AI 基于「几点、在哪、天气」主动关心用户（如「太晚了别熬夜」「有雨带伞」）。

| 数据源 | 获取方式 | 说明 |
|---|---|---|
| 时间 | `System.currentTimeMillis()` | 零成本，时区按本机 |
| 位置 | `FusedLocationProviderClient.getLastLocation()` | 后台只取系统缓存，不主动定位 |
| 位置更新 | 每天第一次打开 App 时前台 `getCurrentLocation()` 一次 | 手动指定城市后不再自动定位 |
| 天气 | Open-Meteo（免费、无需 Key、中国区 CMA 数据） | 前台打开时拉一次并缓存，后台只读缓存 |

- 权限：只申请 `ACCESS_COARSE_LOCATION`，不申请精确定位、不追踪、不存轨迹。
- 环境判断用纯规则（不调模型）：时间 >23:00 或 <05:00 → 熬夜类；降水概率 > 阈值 → 带伞类；温度骤降/高温 → 相应提醒。同时满足多条则分成多条按顺序发。
- 判定后把环境数据作为**环境钩子**喂给生成层，用人设语气说，不套模板。
- 环境钩子优先于记忆钩子；同类环境提醒有冷却期、统计回复率参与降频。
- 天气缓存超过 24h → 跳过天气类关心，不当次联网补拉；天气请求失败 → 退化为只用时间。
- 定位失败 → 手动指定城市或只用时间；隐私：位置只用于当次天气请求，不落库不上传。

### 模块 7：语音唤醒与语音输入（可开关，默认关闭）

| 功能 | 说明 |
|---|---|
| 语音唤醒 | 说唤醒词（如「你好小陪」）唤起 App 进入对话 |
| 语音转文字 | 说话 → 本地 STT → 发给大模型 → TTS 念回复，全程语音 |
| 通知栏快捷入口 | 常驻通知 + PendingIntent，点一下进对话；普通 App 即可，不需 root，进程仍可休眠 |

- **与省电的冲突及处理**：语音唤醒需常驻前台服务+麦克风，与休眠设计冲突。小爱同学靠厂商 DSP 低功耗通道，普通 App 拿不到（root 也拿不到）。因此做成**可开关、默认关闭**；开启则接受常驻通知和耗电，关闭则回到休眠。
- root/ADB 只能解决后台保活（Doze 白名单等，见附录 A），解决不了麦克风耗电。
- 技术选型（离线优先）：唤醒词 Sherpa-ONNX / Porcupine / Vosk；STT 用 Sherpa-ONNX / Vosk / whisper.cpp；不引入云服务。
- 放弃长按电源键唤醒：第三方 App 做不到（系统不分发 `KEYCODE_POWER`），且 root 后要刷模块、破坏可分享性。

### 模块 8：设置

1. **模型与角色**：API Key（自填）、模型选择/切换、人设提示词。
2. **主动消息**：总开关、每日上限（默认 3）、自动勿扰模式（开关默认关 + 时间区间 + 区间内是否发通知的独立开关）、关心触发阈值（熬夜时间点、降水概率阈值）、追问绝对上限（默认 5 次）。
3. **语音**：语音总开关、TTS 引擎选择+默认、语速滑块、朗读方式（点按/自动/只文字）、语音唤醒总开关（默认关）、唤醒词、STT 引擎。
4. **环境感知**：环境关心开关、位置权限引导、手动指定城市。
5. **通知与快捷入口**：通知权限引导（Android 13+）、通知栏常驻快捷入口开关。
6. **系统/调试**：电池优化白名单引导、测试模式按钮、关于页（Open-Meteo 署名+链接）。

> 「新建对话」是顶部栏图标操作，不在设置页。

### 模块 9：UI 设计

参考：DeepSeek 手机端（空状态+顶部）、DeepSeek Harness 手机端（对话态+底部状态栏）。

- 参考图：`参考图-deepseek手机端.png`、`参考图-dsh-harness.png`（工作目录）。
- 顶部栏（两种状态都有）：左上设置图标；右上勿扰图标 + 新建对话图标；「记忆」入口（空态与对话态都显示）→ 记忆管理界面。
- 空状态：屏幕中心软件图标（暂用 DeepSeek 鲸鱼，后替换）+「你好，我想成为你生活中的一部分」+ 底部聊天框。
- 对话态：隐藏中心图标与问候语，按 Harness 显示消息；顶部门保留；底部聊天框保留。
- 底部聊天框：文字输入；右侧「+」图片入口——用官方 API 图片能力，App 不限制格式/大小、原图发送、单轮最多 10 张，API 超限时给明确报错；右侧语音按钮（按住说话）。
- 底部状态栏（对话态）：显示 `tok/s · 缓存命中% · 上下文%` 三项；API 返回数据则显示真实值，未返回则显示 `?? tok/s · 缓存命中 ??% · 上下文 ??%`；始终显示、不隐藏、不伪造。

## 五、附录 A：root / ADB 保活命令

ADB（无需 root，重启后仍生效）：
```
adb shell dumpsys deviceidle whitelist +包名
adb shell cmd appops set 包名 RUN_ANYWHERE allow
adb shell am set-standby-bucket 包名 active
```
root 额外：可把 App 装成系统应用拿签名级权限、直接改系统数据库加白名单（不用 ADB）。
门槛：ADB 要连电脑、开 USB 调试，分享给别人时对方需会这一步。
注意：这些只解决「后台别被杀」，解决不了语音唤醒的麦克风耗电。

## 七、验收标准

**基础**
- 断网不崩溃，恢复联网后继续工作。
- 记忆管理界面可见三层记忆内容/时间/权重，可增删改。

**主动消息与调度**
- 测试模式可完整跑通：决策→召回→生成→顶部通知→点击进对话（含语音）。
- 统一待发队列：多条触发同时发生只发一条，按优先级选（指令>追问>特殊日期>环境>闲聊），不连发。
- 一天主动消息不超过上限（默认 3 条）。
- 自动勿扰：默认关；开启且处于区间时不自动念语音，是否发通知按独立开关；对话手动朗读不受影响。
- 同一记忆钩子不短时间重复召回（已提起标记）。
- 打分三态：默认不加不扣；回复加分；点「别提这个」1 次 30 天冷却到期恢复、2 次永久拉黑（不删记忆）；全被否时退回环境钩子，仍无则跳过。
- 改记忆时若有任务正用旧记忆：该消息照常发，下次用新记忆。
- 指令型提醒（「7 点叫我起床」）：到点必发带语音，绕过冷却/降频/无钩子（勿扰除外）。
- 一次性事件（「明天面试」）走精确闹钟。
- 追问任务：额外 AI 判断追问策略并存任务；「吃了」→结束、「还没」→按间隔再问循环、「来不及不吃了」等语义变体识别为停止；回复判定与 mood 合并为一次调用；到上限或判断失败则停。
- 环境钩子优先于记忆钩子；无合适环境钩子才用记忆钩子。

**心情与特殊日期**
- mood：每轮后一次独立调用更新，输出 JSON（mood+reason），不复用会话 ID、不污染主上下文；失败保持原值。
- 生日/纪念日存长期记忆只录一次，命中当天强制设钩子发祝福。
- 内置节日表：农历用 2026–2036 预生成映射表，运行时只查表；节日命中后基于人设+最近对话生成有语境祝福，不发模板话。

**环境与天气**
- 时间/天气/位置正确进入生成层：夜间「别熬夜」、高降水概率「带伞」。
- 每天第一次打开更新位置缓存，后台只读缓存不主动定位；手动指定城市后不再自动定位；定位失败可用手动城市，不崩溃。
- 天气请求失败退化为只用时间；缓存超 24h 不发天气类关心；同类环境提醒设定时间内不重复。
- 关于页标注「天气数据来自 Open-Meteo」并附链接。

**语音**
- 语音总开关关闭时对话朗读与主动消息语音都不触发；开启时点按能读、主动消息弹出后台自动念、对话整段生成完一次性念。
- 无 TTS 引擎时提示「请安装语音引擎」，不崩溃。
- 朗读期间 WakeLock 正常持有、播完释放，不因休眠中断。
- 语音唤醒关闭时无前台服务/常驻通知、保持休眠；开启时唤醒词→STT→大模型→TTS 链路跑通。
- 通知栏常驻快捷入口：开则显示、点击直达对话；关则不显示；进程仍休眠。

**UI**
- 空/对话态切换正确：无对话显示中心图标+问候语，有对话隐藏并显示消息。
- 顶部三个入口（设置/勿扰/新建对话）可用；「记忆」入口两种状态都显示；底部聊天框两种状态都显示。
- 「+」图片输入：官方 API、原图、App 不限格式大小、单轮最多 10 张，API 超限给明确报错。
- 底部状态栏三项始终显示，缺数据显示 `?? tok/s · 缓存命中 ??% · 上下文 ??%`。
