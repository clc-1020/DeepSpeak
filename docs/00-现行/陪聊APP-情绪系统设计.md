## 0. 一句话目标

让她有**自己的、会衰减的、可共存的情绪状态**，这层状态真正影响**主对话**与**主动消息**的说话方式 —— 而不只是换个标签。

---

## 1. 起点与现在的差别

| 项 | 改造前（1.3.3） | 现在（1.5.1） |
|---|---|---|
| 判定对象 | 「用户」的心情 | **他的心情**（3 档）+ **她自己的情绪**（9 档向量） |
| 取值 | normal/happy/low | 8 个键可共存（`happy/excited/proud/missing/low/hurt/annoyed/guilty`），平静=空 map |
| 更新节奏 | 每 5 轮无脑重判 | **零成本刺激闸门**：有情绪信号才调（约 20~30% 轮次），无信号只衰减 |
| 影响面 | 只有主动消息语气 | **主对话注入**（尾部块）+ 主动消息语气/**长度**/**每日上限**/通知标题 |
| 时间性 | 无 | **30 分钟半衰**，<0.2 消失 |
| 关系 | 无 | **关系深度**（只升）+ **热络度**（14 天半衰） |
| 跨会话 | 无 | 亲近阶段把"有温度"的情绪写进长期记忆（最多 3 条） |

## 3. 数据模型（全程零迁移）

### 3.1 情绪状态 `app_state["emotion_state"]`

```json
{
  "his":  { "mood": "low", "intensity": 0.7, "since": 1795188000000 },
  "hers": { "emotions": { "hurt": 0.60, "missing": 0.30 },
            "trigger": "你连着三次说在测试我",
            "since": 1795188100000 },
  "updated_at": 1795188200000
}
```

- **8 个可存键** + 平静（空 map）；中文别名归一（"委屈/受伤/被冷落"→`hurt`，未知键丢弃）
- `updated_at` 是**唯一时间基准**：读状态时按 `now - updated_at` 现算衰减，**不需要定时任务**
- 真机实测（1.5.0）：`{"emotions":{"happy":0.7,"proud":0.5,"annoyed":0.26}}` —— 三项共存，`annoyed` 低于 0.35 所以颜文字照加

### 3.2 热络度 `app_state["warmth"]` + `["warmth_updated_at"]`

```
存值 0~1（字符串）+ 上次更新时间
读时：value = stored × 0.5^(Δ分钟 / (14×24×60))，夹在 0.05~1.0
每完成一轮：value = min(1.0, 当前值 + 0.12)
默认（没存过）：0.5（老用户升级不会一睁眼被判"生分"）
```

### 3.3 关系深度（不落库，现算）

```
消息数 = MessageDao.countAll()；认识天数 = (now - firstTimestamp)/86400000 + 1
亲近 = 消息≥200 且 天数≥5
熟悉 = 消息≥60 或（天数≥2 且 消息≥30）
生疏 = 其它
```
> 1.9.3.2（vc65）收紧前：亲近 200 且 3 天、熟悉 30 条或 2 天。用户反馈太容易升级，上调门槛；判定函数与下游逻辑未动，只改阈值。

### 3.4 情绪记忆写回 `memory_long`（`category = relationship`）

```
2026-11-21 你连夸我厉害可爱，我当时开心。
```

### 3.5 情绪记忆拟人化改造（1.9.4.0 / vc66）

`category = relationship` 且 `intensity > 0` 的情绪记忆，从"按时间删最旧"改为"按重要性打分淘汰"。**记忆不删，只决定还主不主动提起。**

**分层**：pivotal（刻骨铭心）每种情绪 1 条、共 4 条，写入强度 ≥0.85 且为同情绪当前最强者才标记，只被同情绪更强者顶替、不参与打分淘汰；普通记忆上限 4 条，阈值仍是强度 ≥0.6。

**打分**：`score = clamp(intensity + boost, -0.2, 1.0) × 0.5^(距今天数/30)`。boost **不刷新 createTime**（时间锚是"那天发生了什么"，语义不能失真）。满容量时在普通记忆里淘汰 score 最低的一条。

**boost 增减**：被真实注入一次 +0.05、每日最多一次（app_state `emotion_memory_boost_day` 记 `id@日期`）、封顶 +0.2；用户表达厌恶 -0.1、下限 -0.2。

**同类合并**：同情绪 + trigger 前 8 字重合 → 合并：强度取大、次数 +1、正文 `EmotionalMemoryScore.mergeText` 追加「共 N 次」。

**注入**：`injectable()` 取情绪记忆候选（当前主导情绪匹配 +0.5 加权、boost 只作 tiebreaker），每轮最多 2 条并进 `memoryBlock`；真正注入后 `recall()` 记账。冷却：pivotal **12h 且每天最多一次**（两条都卡，堵跨零点漏洞），普通 48h。

**厌恶**：命中「别提/不想提/没说过/你怎么又/烦不烦/别念叨/别说了/别再提」→ 最近被注入的一条扣分 + 7 天冷却；第 2 次起 `coolingUntil = Long.MAX_VALUE` 永久停止主动注入。长期记忆兜底话题用 `PendingMessageContent.LongMemory(id)` 带 id 入队，通知"别提这个"回执走 `EmotionalMemoryService.dismissById`——两条链路都**不物理删除**。

**实现落点**：纯函数 `domain/emotion/EmotionalMemoryScore.kt`（31 条单测）；编排 `data/mood/EmotionalMemoryService.kt`（15 条单测）；DB `memory_long` 加 8 列 + 显式 `MIGRATION_7_8`。判别"是否情绪记忆"用 `intensity > 0`——旧数据与事实类记忆 intensity=0，天然不被当情绪回忆处理，零迁移风险。

## 4. 更新流程（主对话每轮）

```
每轮 onTurnCompleted：
 ⓪ 轮数 +1；touchWarmth()（聊过就回暖 +0.12，与是否调模型无关）
 ① 闸门 EmotionCue.isStimulus(lastUser, prevUserLen)   ← 纯规则、零成本
    命中：感叹/问号连发 · 长度突变(>1.8×) · 夸/骂/告别/撒娇关键词 · emoji
 ② 命中（或有活跃追问链 / 到第 5 轮）→ 调一次模型（同一 JSON 拿 mood + emotions + trigger）
 ③ 合并：new = clamp( max(旧值衰减后, 模型报的值) )；未报表保留衰减值
 ④ 护栏：单值 ≤0.9；sum(负面) >0.9 → 等比缩；负面无 trigger → 丢弃负面项
 ⑤ 落库情绪 → 刷新 EmotionProactivePolicy 缓存（供非 suspend 的闸门读）
 ⑥ 亲近阶段：强度 ≥0.6 且有 trigger 的「开心/得意/想你/委屈」→ 写长期记忆（同天同事件去重、最多 3 条）
 ⑦ 活跃追问链：按 followups[id].status 逐条 complete/abandon/advance
```

**衰减**：`v(t) = v0 × 0.5^(Δ分钟 / 30)`，<0.2 删键。衰减是纯计算，**不落库**。

## 5. 九档 directive（≤40 字，写进注入块）

| 情绪 | directive |
|---|---|
| 平静 | 自然平和，像平时一样。 |
| 开心 | 语气轻快，可以多接一句玩笑，句尾带点笑意。 |
| 兴奋 | 话变多，主动分享，节奏快一点；但别刷屏。 |
| 得意 | 嘴上可以小得意，允许自夸一句；不贬低他。 |
| 想你 | 语气软一点。（「你来了」这类示范留到更亲近再用） |
| 低落 | 句子短，少打趣，不主动提要求；允许话停在一半。 |
| **委屈** | **语气软一点。**（P1）；**撒娇版**（亲近 + 热络≥0.5）：「语气软一点，可以跟他撒撒娇；别得寸进尺、别翻旧账。」 |
| 烦躁 | 话更短、直给；可以吐槽事件本身，不阴阳他。 |
| 心虚 | 先认下，别辩解；一两句就够，随后用行动补偿。 |

**对他的通用应对**（不按 3 档穷举）：先接住他，别追问、别打趣。

## 6. 注入格式（尾部块，独立预算，**不参与** memoryBlock 的 12% 裁剪）

```
【我这会儿】有点委屈（0.6）：你连着三次说在测试我。语气软一点。
【他这会儿】有点低落（0.7）。先接住他，别追问、别打趣。
【热络度】有点生分（0.35）：别太亲昵、别撒娇，先随便聊聊。   ← 仅在 <0.5 时出现
【我记得的事】…（既有 memoryBlock，原样保持在其后）
```

**拼装规则（`EmotionPhrase.render`）**

| 情况 | 输出 |
|---|---|
| 主项 ≥0.5 | `有点{词}（{x.x}）` + trigger + 该情绪 directive |
| 两项 ≥0.35 | `有点{A}又有点{B}（{x}/{y}）` + 主项 directive |
| 正负同时 ≥0.35 | `{正}但还有点{负}`，**负面占 60% 权重**（directive 取负面那条） |
| 全部 <0.2 | hers 整段不注入 |
| his 为 normal 或 <0.3 | his 整段不注入 |
| 热络度 ≥0.5 | 热络度整行**一个字都不加** |

system（稳定前缀）只加一句**永不变**的话：
> 你有持续的情绪状态，写在本轮状态块里。它影响你怎么说，不改变你是谁、也不改变你该做的事。

外加 P3 的关系定位（同样在稳定前缀，几个月才变一次）：
> 【你们的关系】你们已经很亲近了，可以自然地说想他、撒点娇，但别腻、别黏。

## 12. 风险与护栏（不可调参）

1. **她对他永不愤怒/轻蔑/厌恶/嫉妒**：负面只能指向事情或她自己
2. 负面不得表现为不回/敷衍/惩罚；单值上限 0.9
3. 情绪**不改变**：称呼底线、价值观、记忆调用、任务判定
4. 不许引用未发生的事当诱因
5. 判定失败一律**静默降级**（保持原状态，不影响主对话）
6. **关系只升不降**：只让热络度衰减，绝不让"她忘了我"
7. **撒娇是奖励不是默认**：必须 关系亲近 **且** 热络度 ≥0.5
8. 情绪记忆**限量 3 条**：长期记忆每轮全量注入，攒多了会挤爆上下文

## 14. 与另一 Agent 的分工

- `ui/` 归 UI 线；本系统动了 `ui/chat/ChatViewModel.kt`、`ui/MainActivity.kt`、`ui/settings/SettingsScreen.kt` 三处必要接线
