> **状态：历史** ｜ v1 时期的技术裁决与范围定义，已被 v2 取代。

## 0. 一句话定位

个人自用的安卓陪聊 App：纯客户端、无服务器、电脑不常驻；用户自填 **DeepSeek 官方 API Key**；像真人一样记得用户、按时机有内容地主动找人说话；本地高优先级通知弹出；平时不常驻、靠系统唤醒、干完即睡。

## 1. v1 范围

### 1.1 v1 做（按阶段）

- **阶段0 地基**：工程脚手架、本地存储（Room）、DataStore、DeepSeek 客户端（流式 SSE + usage 解析 + 错误处理）。
- **阶段1 聊天可用**：模型配置页（Key 加密保存/模型选择）、基础对话界面（流式、多轮、本地保存）、人设设定、空态/对话态 UI + 顶部入口 + 底部聊天框 + 状态栏三项。
- **阶段2 记忆系统**：短期记忆、每日日志、长期事实、时间锚点、语义去重、按需召回、淡忘、记忆管理界面、打分三态与「别提这个」。
- **阶段3 心情**：mood 独立轻量调用（JSON 输出，失败保持原值）。
- **阶段4 主动消息**：任务/队列持久化、定时兜底+沉默检测、一次性事件精确闹钟、统一队列调度器、决策闸门、记忆钩子、特殊日期节日（含 2026–2036 农历表）、时间类环境关心、生成层、送达层（本地高优先级通知）、测试模式。
- **阶段5 收尾**：省电与保活（WakeLock/Doze/有网约束/白名单引导）、设置页整合、关于页（含 Open-Meteo 署名）。

### 1.2 v1 暂不做（放到 v1.1 / v2）

| 暂不做 | 放到 | 理由 |
|---|---|---|
| 追问链 / 监督链（原 3.6） | v1.1 单独一期 | 复杂度最高，单独实现单独测试；v1 先跑通一次性提醒+普通主动消息 |
| 天气 / 位置环境感知 | v1.1 | 权限流程+联网缓存变数大；v1 只做零成本时间类关心 |
| 语音朗读 TTS（模块5） | v1.1（可按需提前） | 含异步初始化/朗读保活/勿扰交互，压缩 v1 风险 |
| 语音唤醒 + 语音输入 STT（模块7） | v2 | 默认关、常驻麦克风、MIUI14 耗电无解，后置 |
| 图片输入（"+"入口） | v2 | 已定 DeepSeek 纯文本，砍掉 |
| 分享给别人 / 多人 | 以后 | 每人自填 Key，自用稳定再说 |

## 2. 技术裁决（已拍板，后续不再重复确认）

1. **大模型 = DeepSeek 官方 API，纯文本**。`base_url = https://api.deepseek.com`，默认模型 `deepseek-chat`，可切 `deepseek-reasoner`。图片输入砍掉。
2. **记忆去重/召回 = 纯 DeepSeek 轻量调用判断**（不塞本地模型、不引第三方 embedding）。写入时判重复合并，召回时在候选里选相关项。
3. **每日上限 3 条只约束 AI 自发消息**（环境钩子/记忆钩子/节日祝福/兜底闲聊）；**用户指令提醒、追问链不计入**（各有勿扰 + 自身上限约束）。
4. **定时兜底载体 = AlarmManager `setExactAndAllowWhileIdle` 主唤醒**（保证准点，执行时自查有网、无网重排）；WorkManager 仅作"有网补算"辅路，不当定时器。事件预约用 `setAlarmClock`。
5. **"停留 5 分钟续聊" = 对话页 Activity 前台天然保持；朗读期间用短时前台 Service 托住 TTS，播完即停，不做常驻。**
6. **安卓版本：`minSdk 26` / `targetSdk 34`**，以 MIUI14（≈Android 13）实机为准，适配 Android 14 精确闹钟/通知/前台服务类型权限。

## 3. 技术栈与工程约定（默认，如无异议即采用）

- **语言/UI**：Kotlin + Jetpack Compose（Material 3）。
- **本地存储**：Room(SQLite)、DataStore(偏好)、`androidx.security:security-crypto` 的 EncryptedSharedPreferences 存 API Key。
- **网络**：OkHttp + Retrofit，流式用 SSE 解析；`kotlinx.serialization` 解析 JSON。
- **调度**：AlarmManager + BroadcastReceiver（精确/兜底）、WorkManager（辅路/有网约束）。
- **通知**：NotificationChannel `IMPORTANCE_HIGH`。
- **包名占位**：`com.example.companionchat`（可改）。
- **禁止事项**：不引入服务器/后端；不写死 API Key；不开常驻前台 Service（语音唤醒开启/短时 TTS 除外）；v1 不申请定位/天气权限。

## 4. 数据模型（Room 草案）

| 表 | 关键字段 |
|---|---|
| `conversations` | id, title, created_at, updated_at |
| `messages` | id, conv_id, role(user/assistant/system), content, created_at, is_proactive(bool), prompt_tokens, completion_tokens, cache_hit_tokens, cache_miss_tokens, meta_json |
| `memories` | id, layer(short/long/daily), content, event_time(绝对时间戳), created_at, weight(real), forget_score(real), last_mentioned_at, last_scored_at, status(active/cooldown/blacklist), cooldown_until, source_msg_id |
| `tasks` | id, type(event_reminder / [followup 预留]), task, first_at, need_followup(bool, v1 恒 false), followup_interval_min, stop_condition, state, followups_done, max_followups, created_at |
| `send_queue` | id, task_id, priority(int), enqueued_at, status(pending/sent/dropped/deferred) |
| `mood_state` | id(单行), mood(normal/happy/low), reason, updated_at |
| `relation_summary` | id(单行), summary, updated_at |
| `settings`（或 DataStore） | key, value |

- **节日表**：`assets/festivals_2026_2036.json`（农历/公历预生成映射，运行时只查表；2036 后发新版更新）。
- **时间锚点**：写入记忆前把「下周三/明天」等相对时间换算成绝对时间戳存 `event_time`。

## 5. 功能清单（含依赖顺序与验收要点）

> 一次只做一个功能；依赖未完成不开工；做完更新 §8 进度表并写自测。

### 阶段0 地基
- **F1 工程脚手架 + 存储初始化**：Compose 空壳、Room/DataStore 建库、目录结构。验收：能启动空页、建表成功。
- **F2 DeepSeek 客户端**：SSE 流式、usage 解析（`prompt_cache_hit_tokens/prompt_cache_miss_tokens/prompt_tokens/completion_tokens`）、超时/限流/断网错误封装。验收：能流式打印、断网不崩、可重试。

### 阶段1 聊天可用
- **F3 模型配置页**：Key 加密保存、读取、模型选择/切换。验收：重启后 Key 仍在且非明文。
- **F4 基础对话**：多轮上下文、流式渲染、消息落库、发送/失败重试、流式中断保留已收内容。验收：连续多轮正常，断网恢复可续。
- **F5 人设设定**：system prompt 可编辑并参与生成。验收：改人设生效。
- **F6 主页 UI**：空态（中心图标+问候语）↔ 对话态切换；顶部（设置/勿扰/新建对话/记忆入口）；底部聊天框；底部状态栏三项 `tok/s · 缓存命中% · 上下文%`（缺数据显示 `??`，不伪造）。验收：两态切换正确、状态栏真实/未知正确。

### 阶段2 记忆系统
- **F7 时间锚点工具**：相对时间→绝对。验收：单测覆盖常见表达。
- **F8 短期记忆 + 每日日志**：写入事件流水带绝对时间，短记忆带淡忘分初值。验收：新对话产生记忆。
- **F9 长期事实层**：稳定事实/偏好跨会话。验收：跨会话可召回长期事实。
- **F10 语义去重**：DeepSeek 轻量判断，重复则更新旧记忆、不膨胀。验收：重复表述不新增条目。
- **F11 按需召回**：打分 `得分=时间新鲜度×权重+(当前-上次提起)×久未提及加分-淡忘分`，选 TOP1 / 按需 ≤6 条/≤8000 字。验收：召回相关、非最近一条。
- **F12 淡忘机制**：不删，仅越来越难召回，内容可查。验收：老记忆召回优先级下降。
- **F13 记忆管理界面**：三层查看（内容/时间/权重）、增删改。验收：可手动加「记住我对花生过敏」并生效。
- **F14 打分三态 + 别提这个**：默认不加不扣；回复加分；点一次降权+30 天冷却到期恢复、点两次永久拉黑（不删）。验收：三态行为正确。

### 阶段3 心情
- **F15 mood 独立调用**：system+最近 3~5 轮+当前 mood→JSON `{mood,reason}`；独立调用不复用会话 ID、不写回主历史；失败保持原值。验收：失败不影响主对话。

### 阶段4 主动消息
- **F16 任务与队列持久化**：`tasks`/`send_queue` 建表与读写。验收：重启队列不丢。
- **F17 定时兜底 + 沉默检测**：`setExactAndAllowWhileIdle` 周期自预约，有网自查无网重排。验收：准点唤醒、省电。
- **F18 一次性事件精确闹钟**：`setAlarmClock`。验收：「明天 9 点面试」到点触发。
- **F19 统一队列调度器**：优先级 指令提醒>追问>节日>环境>闲聊，同级按时间，串行出队，出队统一查冷却/勿扰/上限。验收：多触发同时只发一条、按优先级。
- **F20 决策闸门**：勿扰（区间内不自动念语音，是否通知按独立开关）、冷却（距上次交互<2h 不发）、回复率（7 天，<20% 降到一天一次）、每日上限（AI 自发≤3）、无钩子不发。**指令提醒绕过冷却/降频/无钩子，仍受勿扰；不计入每日上限**。验收：各闸门单测通过。
- **F21 记忆钩子生成**：召回→打分→TOP1→生成→标记「已提起」防复读。验收：短时间不复读同一钩子。
- **F22 特殊日期节日**：生日/纪念日存长期记忆（只录一次），命中当天强制钩子；内置 2026–2036 节日表；命中后基于人设+最近对话生成有语境祝福（非模板）。验收：命中即发、非模板。
- **F23 时间类环境关心**：纯规则（>23:00 或 <05:00 熬夜类等），作环境钩子喂生成层。验收：夜间触发「别熬夜」类。
- **F24 生成层**：钩子（环境/记忆/节日）+关系摘要+最近几条对话+mood+环境→DeepSeek 生成。验收：话语有语境、不像模板。
- **F25 送达层**：`IMPORTANCE_HIGH` 本地通知顶部弹出→点击进对话并插入历史。验收：点击直达且消息在历史中。
- **F26 测试模式按钮**：立即触发一次完整链路（决策→召回→生成→通知）。验收：一键跑通。

### 阶段5 收尾
- **F27 省电与保活**：WakeLock 用完即释、Doze 穿透、有网约束、电池优化白名单引导（附录 A）。验收：不因休眠漏推送。
- **F28 设置页整合**：模型与角色、主动消息（总开关/每日上限/勿扰开关+区间+区间内发通知独立开关/阈值）、环境关心开关、通知权限引导（Android 13+）、测试按钮、关于页（Open-Meteo 署名+链接）、电池优化引导。验收：各项生效。

## 6. 主动消息调度规则（合成版，唯一事实源）

1. 所有触发源（定时兜底/事件预约/特殊日期/环境钩子/记忆钩子）**不直接发**，统一投 `send_queue`，由**单个调度器串行处理**。
2. **出队优先级**：`用户指令提醒 > 追问链 > 特殊日期/节日 > 环境钩子 > 定时兜底闲聊`（同级按时间；资源冲突时低优先级丢弃或顺延）。
3. **闸门在出队时统一检查**：勿扰 > 冷却(2h) > 回复率降频 > 每日上限(AI 自发≤3) > 无钩子不发。
4. **豁免**：用户指令提醒绕过"冷却/降频/无钩子"，仍受勿扰；指令提醒与追问链不计入每日 3 条上限。
5. **勿扰**：区间内不自动念语音；是否发通知由勿扰模式独立开关决定；对话手动朗读不受影响。

## 7. 项目规则（给每次开发的 AI）

- 开工前**必读**本文件 + §5 功能清单 + §8 进度表；确认依赖功能已完成。
- **一次只实现一个功能**，不擅自跨功能合并、不一次性做完全部。
- 用 §3 约定的技术栈；偏离需在 §9 记录原因。
- 实现后：更新 §8 进度（状态/日期/备注）、补充新约定到本文件、写验收自测结果。
- 代码风格：Kotlin 惯例、Compose 组合式 UI、严格区分 UI/领域/数据层。
- 安全：Key 只进 EncryptedSharedPreferences；日志不打印 Key/正文敏感内容。
- 隐私：v1 无定位/天气；聊天与记忆仅存本机。

## 9. 矛盾修复与待定项记录

### 9.1 已解决的矛盾

| 原矛盾 | 处理 |
|---|---|
| A1 "官方 API"未指名 + 与图片输入冲突 | 定为 DeepSeek 官方 API 纯文本；v1 砍图片输入 |
| A2 定时兜底 WorkManager vs setExactAndAllowWhileIdle | 主用 AlarmManager 精确唤醒，WorkManager 仅辅路 |
| A3 每日上限与指令/追问边界不清 | 每日 3 条只算 AI 自发；指令+追问不计入 |
| A4 执行完退出 vs 停留 5 分钟续聊 | Activity 前台保持 + 朗读用短时前台 Service，不常驻 |

### 9.2 补齐的缺口（v1 已纳入）

记忆算法（DeepSeek 判断）、数据模型、上下文预算（记忆≤6 条/8000 字 + 关系摘要 + 最近 N 轮 + mood/环境，超按优先级截断；上下文%=已用 tokens/模型窗口）、API Key 加密、主对话失败兜底、安卓版本与权限。

### 9.3 三个待定项状态

1. **TTS 引擎检测**：实现期调研题（v1.1 做 TTS 时解决），不影响当前架构。
2. **语音唤醒 MIUI14**：维持"默认关闭的可开关方案"，省电+唤醒无解。
3. **遗漏功能**：后续想到再追加进 §5。
